From CRAN (the Comprehensive R Archive Network):

  • R is a system for statistical computation and graphics. It consists of a language plus a run-time environment with graphics, a debugger, access to certain system functions, and the ability to run programs stored in script files.

Translation:

  • R is a language with an interpreter and a standard library (toolkit/toolbox of functions)
  • With execution support code (behind the scenes code that helps your R code run on your computer)
  • All for the practice of statistics (involves computation,simulation, data visualization etc.)
  • R can also monitor/analyze code, identify coding errors, interact with your operating system, run programs saved on your computer as scripts (or similar) among other things.

The “BIG” Question

Why R and not Python?

  • The basic difference: R was built by statisticians for statisticians, so the focus is narrower.
  • Python was built by software engineers for general purpose applications, so the focus is broad.
  • R is great for focusing on thinking about statistical problems, solving them, and communicating the results
  • Python is great for doing lots of different things. Example, download thousands of YouTube videos, analyze the images frame by frame, transcribe the sound into words, analyze the data, etc.

Why R and not Python? (cont’d)

  • R is “Problem-First” or “Problem-Forward”
  • In R, data structures are integrated directly into the language and do not require additional tools (but tools, found in libraries, are helpful).
  • When you load a dataset, R assumes you want to analyze it. The syntax is designed to mirror the way a researcher thinks: “Take this data, then filter it, then group it, then summarize the mean, etc.”
  • Also R’s simpler modeling formulas allows one to remain thinking about the analytical problem.

Why R and not Python? (cont’d)

  • Python is “System-First”
  • In Python, you “build” your environment before you can solve the problem (importing tools, found in libraries such as pandas, numpy, etc.)
  • In Python, it matters how the code integrates within a larger system, the result is versatility. So it is easy for Python to interact with YouTube for example (not as easy/or maybe not possible in R)
  • In R, what matters is how the programming code helps you reveals the truth in the data.

The “Formula” vs. “The Matrix”

In R, a statistical model is treated like a scientific hypothesis. In Python, it is treated like how the computer wants its input formatted.

  • R Approach: You use formulas (y ~ x). This is like saying “I think \(y\) is a function of \(x\).” R automatically handles things like creating “dummy variables” for categorical information (e.g., turning “Species” into 0s and 1s) and keeps the names of your variables intact so you can read the results.
  • Python Approach: Most Python libraries require you to manually transform your data into a matrix of numbers first. You then “One-Hot Encode” your categories and strip away the column names, then pass them in as \(x\) and \(y\).

In R, the code looks like the math inside your head. In Python, the code looks like the way the computer understands math.
